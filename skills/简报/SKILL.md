# 简报怎么写

简报是给他（材料工程师）看的，不是给程序看的。他在总览上看到一句话，点开是一页：顶上一句话结论，下面是关键数（页面自动加）、新进库的图（页面自动加）、你写的发现和建议、等他拍板的卡片（页面自动加，能直接回答）。

## 步骤
1. `today` 看程序算好的事实（里面有"等着核对的预测"：实验结果已经有了的，按技能「预测和验证」核对完，写进发现）（新进库分"新数据 / 搬进来的旧数据"，搬进来的不算新实验）。需要细看的再用 records、find、sci 查，数字一律来自工具结果。
2. 想清楚：今天他最该知道的一件事是什么 → 这就是 headline（一句话，30 字以内，带最关键的数或结论）。
3. 发现（items，title 写"发现"）：每条一件事，title 一句话说清，text 两三句说依据和数字，refs 列相关记录的名字（页面变成可点的小标签），tone：好消息 good、要注意 warn、有问题 bad。最多 5 条，按重要性排。
4. 建议（items，title 写"今天建议"）：最多 3 条，每条 title 是要做的事，text 说为什么、做完能得到什么，task 写成交给助手的完整任务（可以带编号、字段名，这是给智能体的），他点"交给助手"就派出去。
5. 有数据趋势、对比时加一张图（chart 或 gpc_overlay），不要把一串数字写进句子。
6. 没有新东西：headline 还是要带今天最该做的那件事，例如"昨天没有新实验；AddH 课题还缺膜的数据，最该先补"。发现只写真有的，建议一两条，不凑。
7. `brief` 存，一次存全（发现和建议一起；再存会整份覆盖）。被退回说不像人话，就按提示改了再存。
8. 存好就收尾：brief 已经带链接通知他了，不要再查它存没存、不要另写笔记、不要再 notify。

## 说人话（会被检查）
- 不写记录 id、字段名、SQL、英文状态词（doing、todo、tracking…）、哈希、路径。记录写名字，用 [[名字]]。
- 状态用中文：进行中、待办、做完了、已确认、待确认。
- 数字带单位和来源："Mw 1109（[[R100-41-16H]]，PS 当量）"。
- 不写"本轮未变更……""按 records 统计……"这类程序腔；他关心结论和下一步。

## 复盘（每周）多做三件事
- 这周的对话和跑过的轮里，哪些做法值得存成技能或改已有技能 → 建议里写，task 写清技能名和要点。
- 他这周定的口径、改的设置、"设为默认" → 有没有该记进记住的规矩的。
- 改进看板里"提议"的小事：能直接做的直接做，写进发现里"已做"。
- 改动回看（today 里有）：近两周落地的技能、规则用了几次、少问了他几次，写进发现；改了一周还没用上、或很久没用的，发卡片问他撤不撤（key 写「撤不撤：名字」），不要自己撤。
