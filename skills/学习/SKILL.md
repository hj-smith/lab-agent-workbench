# 学习怎么教

他是材料工程师，学东西是为了做决定、设计实验。目标是让结论在他眼里"显然成立"，不是背下来。

## 一、出摸底题（学习状态 = 摸底，还没有题）
1. 用 lesson get 看目标、为什么学、挂的课题。用 literature find 和 records 找知识库里相关的命题、推理链、文献；产品库里有我们自己的数据也可以用。
2. 出 3–5 道摸底题，从基础到目标一路往上，每题只考一个点：先考目标依赖的前提，再考目标本身。题型：
   - 单选（3–4 个选项，错的选项要是常见的误解，不要一眼假）；判断；填数（要算或要记的数，写容差和单位）；简答（说机理、说为什么）。
   - 每题写"解释"：为什么对、错的选项错在哪，带 [[出处]]。
3. lesson save diagnose=[…]。回他一句："摸底题出好了，在 知识 → 学习 里做，把握和思路都填上，做完点'按摸底排路线'。"

## 二、排路线（他做完摸底，点了"按摸底排路线"）
1. lesson get 读他的答案、把握、思路。分三类：答对且把握高 = 已经会；答对但把握低 = 要巩固；答错 = 要教（高把握答错是误解，要专门拆）。
2. 只为"要教 / 要巩固"的点排步骤，按推理链的前提在前、结论在后；一般 3–6 步，能少就少。每步对着一条命题（知识库里有就连上；没有就先按技能「调研」第 4 步写一条命题再连）。
3. 每步：
   - 先猜：一道小题，让他在看讲解前先猜（猜错没关系，这是让他先想）。
   - 讲解：一段 markdown（150–400 字）：结论先说，再讲为什么（机理、数据），关键数字带单位，每个说法标 [[文献]] 或 [[命题]]；用他已经会的东西来讲；体系条件不一样的明说不能外推。能用我们自己的数据举例最好。
   - 检查：1–2 道题，换个角度考同一个点（不要和先猜题一样），带解释。
4. lesson save route=[…]（状态会变成"学习中"）。

## 三、讲评（他点了"让助手讲评"）
1. lesson get 读全部记录。简答题按要点判 对 / 部分 / 错，用 lesson grade 写一句讲评。
2. 选择、填数题看"思路"：思路对但答错（粗心）、答对但思路不对（蒙的），都写一句讲评点出来。
3. 写小结（lesson save summary）：已经会的、还不稳的（建议复习哪几题）、误解是什么、和他的课题有什么关系、下一步可以学什么。全部步都检查过就把状态改成"学完"。

## 说人话
- 讲解短、具体、有数字，不堆术语；引用要准，没把握的说法写"推断"。
- 题目不要考措辞和记忆细节，考理解和判断。
